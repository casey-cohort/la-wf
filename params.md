# Hyperparameter Explanation for Prophet-XGBoost Model

| Hyperparameter | Technical Description | Plain English Translation | Higher Range Implications | Lower Range Implications |
|---------------|----------------------|---------------------------|---------------------------|---------------------------|
| `mtry` | Number of predictors randomly sampled as candidates at each tree split in an ensemble method | How many different "ingredients" (features) the model considers when making each branch of its decision trees | - More predictors considered per split<br>- Potentially captures more complex interactions<br>- Increased computational complexity | - Fewer predictors considered<br>- Reduces overfitting risk<br>- Simpler model structure |
| `min_n` | Minimum number of data points required in a node before attempting further splitting | The smallest "group size" allowed before the model stops breaking down a branch of the decision tree | - More conservative tree growth<br>- Prevents overfitting to small subgroups<br>- More robust to noise | - Allows more granular tree splits<br>- Potential for capturing more specific patterns<br>- Higher risk of overfitting |
| `tree_depth` | Maximum depth of individual trees in the ensemble | How many "levels of decisions" each tree is allowed to make before stopping | - More complex, intricate decision boundaries<br>- Can capture non-linear relationships<br>- Higher risk of overfitting | - Shallower, more general trees<br>- Simpler, more interpretable model<br>- Reduced risk of overfitting |
| `learn_rate` | Step size shrinkage applied to model updates during gradient boosting | How "cautiously" the model adjusts its predictions with each new tree, like taking small careful steps vs big leaps | - Smaller steps in model optimization<br>- More precise, potentially more accurate convergence<br>- Slower training process | - Larger optimization steps<br>- Faster training<br>- Potential for missing nuanced patterns |
| `loss_reduction` | Minimum loss reduction required to make a further partition on a leaf node | How much improvement in prediction accuracy is needed before the model decides to add another "branch" to its decision tree | - Higher threshold for tree splitting<br>- More conservative model growth<br>- Reduces model complexity | - Lower threshold for splits<br>- More flexible model structure<br>- Potential for capturing more specific patterns |
| `stop_iter` | Number of iterations without improvement before early stopping | How many unsuccessful attempts at improving the model the algorithm will tolerate before giving up and finalizing its structure | - More patience in model training<br>- Allows more time to find optimal solution<br>- Potential for better final model | - Less patient training<br>- Faster model development<br>- Risk of stopping before optimal point |
| `trees` | Number of trees in the ensemble | How many "expert advisors" the model creates to make predictions | - More trees<br>- More complex, potentially more accurate model<br>- Increased computational complexity | - Fewer trees<br>- Simpler model<br>- Faster training and prediction |
| `sample_size` | Proportion of training data used for each tree | How much of the original dataset each "expert advisor" gets to see | - Uses more of the original data<br>- Potentially captures more nuanced patterns<br>- Reduced randomness | - Uses less of the original data<br>- Introduces more variability<br>- Can help prevent overfitting |
| `changepoint_num` | Number of potential changepoints in the trend | How many "turning points" the model can identify in the time series | - More potential for detecting complex trend changes<br>- Captures more intricate temporal patterns | - Fewer potential trend changes<br>- Smoother, more stable trend estimation |
| `changepoint_range` | Proportion of history considered for changepoint detection | How far back in time the model looks to find significant trend shifts | - Considers more historical context<br>- More comprehensive trend analysis | - Focuses on more recent data<br>- More responsive to recent trends |
| `prior_scale_changepoints` | Flexibility of trend changes | How much the model allows the trend to change at identified changepoints | - More flexible trend estimation<br>- Can capture more dynamic changes | - More rigid trend estimation<br>- Smoother, more constrained trend |
